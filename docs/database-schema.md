# Database Schema

Current production database is hosted on Supabase.

This document is the source of truth for the database schema, relationships, and database-level search capabilities.

All SQLAlchemy models, repositories, services, and AI assistants must follow this document.

---

# Database Architecture

```text
Supabase
│
├── PostgreSQL
├── pgvector
├── Full Text Search
├── RPC Functions
└── Storage
```

The backend communicates with the database exclusively through the Supabase Python SDK.

Business logic must NOT be implemented inside the database.

Database functions only provide primitive retrieval operations.

## resumes

Purpose

Store uploaded and parsed resumes.

Resume is always saved before AI enrichment.

Fields

- id
- candidate_uuid
- filename
- file_path
- text_content
- created_at

---

## enrichment_profiles

Purpose

Store AI structured candidate information.

Generated by the LLM enrichment pipeline.

Fields

- id
- candidate_uuid
- enrichment_status
- skills
- summary
- experience
- github
- linkedin
- semantic_tags
- skill_matrix
- match_confidence_score
- score_increase
- created_at
- updated_at

Notes

- skills are used only for hard filtering.
- summary, experience, github and linkedin are used for retrieval.
- github and linkedin may be NULL.
- enrichment failure must never delete resumes.

# Database Search Functions

The database exposes primitive retrieval functions through PostgreSQL RPC.

Repositories should call these functions through the Supabase SDK.

---

## get_candidate_ids_by_skills()

Purpose

Hard filter candidates by required skills.

Input

```text
required_skills : text[]
```

Output

```text
candidate_uuid
```

Repository

```text
EnrichmentRepository.get_candidate_ids_by_skills()
```

---

## search_similar_embeddings()

Purpose

Dense semantic retrieval using pgvector cosine similarity.

Input

```text
query_embedding

top_k

candidate_ids (optional)

source_types (optional)

minimum_similarity (optional)
```

Output

```text
candidate_uuid

enrichment_profile_id

source_type

matched_text

similarity_score
```

Repository

```text
EmbeddingRepository.search_similar_embeddings()
```

Notes

- Uses pgvector cosine similarity.
- Supports candidate pre-filtering.
- Supports source filtering.
- Does NOT perform ranking.

---

## search_profiles_lexically()

Purpose

Lexical retrieval using PostgreSQL Full Text Search.

Input

```text
query

top_k

candidate_ids (optional)
```

Output

```text
candidate_uuid

enrichment_profile_id

lexical_score

matched_fields
```

Repository

```text
EmbeddingRepository.search_profiles_lexically()
```

Notes

Searches

- summary
- experience
- github
- linkedin

Does NOT search

- skills

Skills are filtered separately.

# Repository Responsibilities

Repositories communicate with Supabase using the Python SDK.

Repositories may

- CRUD
- call RPC
- query tables

Repositories must NOT

- perform ranking
- call LLMs
- generate embeddings
- orchestrate business logic
